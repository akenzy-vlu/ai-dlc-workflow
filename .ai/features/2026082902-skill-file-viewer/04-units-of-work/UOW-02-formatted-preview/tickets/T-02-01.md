# T-02-01 — Markdown preview + syntax highlighting

## Context

The one file this ticket changes, `skill-file-content.tsx`, was built in T-01-06 to
render raw text for every file on purpose — this ticket is the entire "formatted"
increment ADR-03 describes, kept as a single ticket (not split by concern) specifically
to avoid two tickets touching the same file with no real ordering dependency between
them (see UOW-02's Risks table).

## Implementation notes

- Add `react-markdown` and `highlight.js` to `apps/web/package.json` (ADR-03).
- `skill-file-content.tsx`: when the selected file's extension is `.md`, render via
  `react-markdown` by default, with a "Plain text" toggle that switches to the existing
  raw `<pre>` rendering from T-01-06 (AC-04). State for the toggle is local to this
  component, reset on file change.
- For every other text file (`encoding === 'utf8'`, not `.md`), wrap the raw content in
  `highlight.js`'s highlighter using a language resolved from `highlight-language-map.ts`
  (`.py` → `python`, `.yaml`/`.yml` → `yaml`, `.json` → `json`, `.sh`/`.bash` → `bash`,
  anything unmapped → no language, i.e. `highlight.js`'s plain/auto path so an unknown
  extension degrades to plain text rather than erroring — A-08).
- The binary-placeholder and truncated-notice behavior from T-01-06 is unchanged — this
  ticket only changes the `encoding === 'utf8'` rendering path.
