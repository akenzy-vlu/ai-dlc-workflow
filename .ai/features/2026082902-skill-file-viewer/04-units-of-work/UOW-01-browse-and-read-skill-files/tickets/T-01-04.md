# T-01-04 — SkillFile domain entity + repository port

## Context

The web app's clean-architecture layering (`domain/entities`, `domain/repositories`)
needs its own shape for a skill file, separate from the existing `Skill` entity —
mirroring how `skill.entity.ts` / `skill.repository.ts` are already one pair per concept
in this codebase. This ticket has no runtime dependency on the API being built yet: the
shape comes straight from the Contracts section of `03-logical-design.md`, which is
already pinned — that is what lets this run in parallel with T-01-01..T-01-03.

## Implementation notes

- `skill-file.entity.ts`: a `SkillFileNode` type/class (`relativePath`, `name`,
  `isDirectory`, `extension`, `size`) and a `SkillFileContent` type/class
  (`relativePath`, `content`, `encoding: 'utf8' | 'binary'`, `truncated`, `size`) — the
  exact fields `03-logical-design.md`'s Domain model section defines.
- `skill-file.repository.ts`: a port interface with the two read operations the drawer
  needs, following `skill.repository.ts`'s existing shape (hook-returning methods, e.g.
  `useSkillFiles(skillId)`, `useSkillFileContent(skillId, path)`) rather than inventing a
  different calling convention for this one feature.
- Export both from their respective `index.ts` barrels, same as every other entity/port
  in these directories.
