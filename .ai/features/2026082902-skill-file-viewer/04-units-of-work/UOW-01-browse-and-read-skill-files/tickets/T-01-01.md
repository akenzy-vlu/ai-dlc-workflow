# T-01-01 — readPackageFile() with traversal guard, truncation and binary detection

## Context

`skill-digest.ts` already owns `listPackageFiles(packagePath)` — the recursive walk used
by both the catalog and the installer, and the routine `00-intent.md`'s Reuse constraint
requires this feature to build on rather than duplicate. This ticket adds the one thing
that does not exist yet: reading a single file's content by a caller-supplied relative
path, safely.

The security constraint (`00-intent.md`) and ADR-02 (`03-logical-design.md`) require the
same idiom `browse-directories.query.ts` already uses: resolve the joined path with
`path.resolve`, then require the result to equal the package root or start with
`root + path.sep`, refusing otherwise. `RefusedError` (`apps/api/src/shared/kernel`) is
the existing error type for exactly this shape of refusal.

## Implementation notes

- Add `readPackageFile(packagePath, relativePath, opts?)` alongside `listPackageFiles`
  and `digestPackage` in `skill-digest.ts`.
- Guard first: resolve `path.join(packagePath, relativePath)`, `path.resolve` it, and
  require it to stay under `path.resolve(packagePath)` — throw `RefusedError` before any
  `fs` call if it does not. This must reject `../` segments, an absolute-path override,
  and a symlink that resolves outside the root.
- After the guard passes: read the file. If it is not valid UTF-8 text (or fails a
  binary sniff — e.g. a null byte in the first chunk), return `{ encoding: 'binary' }`
  with no `content` (AC-07) instead of throwing.
- If the file's byte size exceeds a cap (propose `1_000_000` bytes, per A-06), read only
  up to the cap and return `{ truncated: true }` alongside the partial content — this is
  not an error path (see Error taxonomy, `03-logical-design.md`).
- `listPackageFiles`'s existing `IGNORED` set (`__pycache__`, `.git`, `node_modules`,
  `.DS_Store`, `.venv`, `venv`, `.pyc`/`.pyo`) already keeps this feature's file tree
  clean (AC-03) — no change needed there, just a test proving it stays true for this new
  consumer.
- Return shape should carry what `SkillFileContent` (`03-logical-design.md` Domain model)
  needs: `relativePath`, `content`, `encoding`, `truncated`, `size` — this ticket doesn't
  own the DTO (that's T-01-03), just the function producing the data.

## Done when

- [x] `readPackageFile` refuses a `relativePath` containing `../` segments that escape
      the package root, before touching the filesystem — tested directly, not just
      by the endpoint (AC-08)
- [x] `readPackageFile` refuses an absolute-path override (e.g. `/etc/passwd`) the same way
- [x] A file over the size cap comes back with `truncated: true` and partial content, not
      an error (AC-06)
- [x] A non-text file comes back with `encoding: 'binary'` and no `content` (AC-07)
- [x] A normal `.md`/`.py` file under the package root reads back its exact content
- [x] A test confirms `listPackageFiles` output for a fixture package excludes every
      `IGNORED` entry (AC-03)
- [x] `python3 -m py_compile` equivalent for TS: `pnpm --filter @aidlc-console/api typecheck` passes
