# T-01-05 — Skill file RTK Query endpoints + model + mapper + repository impl

## Context

Implements `SkillFileRepository` (T-01-04) against the two routes T-01-03 defines in
`03-logical-design.md`'s Contracts section — `GET /api/skills/:id/files` and
`GET /api/skills/:id/files/content?path=...`. Written against the documented contract, the
same way the template's own reference ticket "codes against a mock... so the swap is
isolated" — this does not depend on T-01-03 being merged, only on the contract it also
implements.

## Implementation notes

- `skill-file.endpoints.ts`: RTK Query `listSkillFiles(skillId)` (query) and
  `getSkillFileContent({ skillId, path })` (query) — mirror `skill.endpoints.ts`'s
  existing shape (query builder, response typing).
- Register a `'SkillFile'` tag in `api.ts`'s tag list, alongside the existing `'Skill'`
  tag — these endpoints are pure reads with nothing to invalidate on this feature's own
  mutations (there are none), but the tag keeps cache-tag wiring consistent with every
  other endpoint in this file.
- `skill-file.model.ts`: wire DTOs mirroring `SkillFileNodeView` / `SkillFileContentView`
  from `03-logical-design.md`.
- `skill-file.mapper.ts`: `toSkillFileNode` / `toSkillFileContent`, model → domain entity,
  same shape as `skill.mapper.ts`'s `toSkill`.
- `skill-file.repository.impl.ts`: implements `SkillFileRepository` using
  `adaptQuery`, same idiom `skill.repository.impl.ts` already uses.
