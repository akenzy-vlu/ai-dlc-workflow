# T-04-03 — aidlc flow, and one flow line in aidlc status

## Context

The command surface for T-04-02's fold. `status` is described in `SKILL.md` as "the answer
to 'what do I do next' throughout", so the one thing it gains should be actionable — what is
aging and what is blocked — not a metrics dump.

## Implementation notes

- `aidlc flow [--aging-hours N]`, non-mutating, so it takes no lock: per-ticket cycle time,
  review lag, blocked time and bias, then the feature totals with the unknown count.
- Threshold precedence: the flag, then `evidence.aging_hours`, then a default.
- Render unknown as `—`, never `0` or `0.0h`.
- `status` gains **one** line: tickets aging past the threshold, and tickets blocked. Below
  G3 it stays as it is — there are no tickets to measure.
- Say where it is documented that these are per-ticket and per-feature numbers, never per
  actor. A trail that records who did what becomes a performance measure the moment
  somebody groups by `by`, and that is not what it is for.
