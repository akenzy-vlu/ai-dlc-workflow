# T-04-02 — flow.py — fold the trail into cycle time, review lag, blocked spans and bias

## Context

Every timestamp this needs has been written since the trail existed: 104 events across the
three plans closed in this repo, each carrying `ts`, `by` and `action`. `cmd_audit` prints
them as a list and nothing folds them. Per ADR-05 the fold is computed on every invocation
and stored nowhere, so a metric can never disagree with the record.

A separate module because `project_registry.py` must import the same fold rather than
reimplement it — the way `aidlc.py` already imports `uow_graph` instead of re-parsing
frontmatter, and for the same reason.

## Implementation notes

- Pure functions over a history list. No filesystem, no argparse — those belong to T-04-03.
- Per ticket: cycle time (`accept − start`), review lag (`accept − submit`), blocked time
  (summed `unblock − block` spans), and bias (cycle time − `estimate`).
- **An unpairable span is unknown, never zero.** A ticket accepted with no start event, a
  block with no unblock, a plan predating a transition — all report as unknown. Zero would
  read as "instant" and quietly flatter every average.
- A still-open span (blocked now, in progress now) measures to *now*; that is what makes
  aging work.
- `aging(tickets, hours)` returns tickets in progress longer than the threshold.
- Feature-level bias is the sum of known cycle times against the sum of their estimates,
  with the count of unknowns reported alongside — an average that hides its sample size is
  the thing this whole methodology exists to avoid.
