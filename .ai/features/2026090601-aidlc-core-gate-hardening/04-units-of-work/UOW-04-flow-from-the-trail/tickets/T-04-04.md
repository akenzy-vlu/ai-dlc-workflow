# T-04-04 — Project flow into project_registry.py and add the Flow and Stuck report sections

## Context

`report()` already answers the portfolio questions no single file can — Portfolio, Waiting
on a human, Pickable right now, Risk concentration, Provenance, Freshness. It has no time
dimension at all. This adds one, across every scanned repo.

The registry's contract holds: plan tables stay disposable, so these columns are derived on
every `--scan` and never become a second source of truth. `gate_event` and `snapshot_log`
stay the only append-only tables.

## Implementation notes

- Import the fold from `flow.py` the way `load_uow_graph()` already imports `uow_graph`.
  Do not reimplement the metric — two implementations of one number is how they diverge.
- `ticket` gains `cycle_hours`, `review_hours`, `blocked_hours`, nullable. Null means
  unknown and must survive into the report as `—`.
- New **Flow** section: median cycle time, median review lag and estimate bias per repo,
  with the unknown count. Median rather than mean — one abandoned ticket left open for a
  month should not redefine a team's cycle time.
- New **Stuck** section: aging and blocked tickets across every repo, with the block reason.
  This is the cross-repo standup list, next to the existing "Waiting on a human".
- `--ingest` path: a snapshot from an older tool has no flow fields. Ingest it with nulls
  rather than refusing — the registry's job is to accept what repos actually ship.
