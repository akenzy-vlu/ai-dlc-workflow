# T-01-01 — normalise_actor() and last_ticket_event() helpers

## Context

`read_history` already returns the trail sorted deterministically by `(ts, id)`, and every
ticket transition is appended with `{"action": "ticket <target>", "by": ..., "ticket": ...}`.
The data needed to answer "who submitted this ticket" is therefore already on disk and has
never been read back. This ticket adds only the two pure functions that answer it; the
refusal that uses them is T-01-02.

## Implementation notes

- `normalise_actor(name)` — strip surrounding whitespace, collapse internal runs of
  whitespace to one space, casefold. `"  CLAUDE "` and `"claude"` are the same actor
  (AC-04). Return `""` for `None`.
- `last_ticket_event(history, ticket, action)` — the last entry matching both `ticket` and
  `action`, or `None`. Take it from the tail of the already-sorted list; do not re-sort.
- Both are pure and take the history list, not a directory — that is what makes them
  testable from a scratch trail without a feature on disk.
- No behaviour changes in this ticket. Nothing calls them yet.
