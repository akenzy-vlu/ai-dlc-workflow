# T-01-02 — _transition refuses an acceptance from the submitting actor

## Context

`_transition` (`aidlc.py:961`) currently allows `done` from `review` without looking at who
is asking. This is the hole `SKILL.md` already claims is closed. The refusal belongs before
any write: the ticket file must be untouched when the transition is refused, which the
existing ordering already gives us — the status rewrite happens after all checks.

## Implementation notes

- Only when `target == "done"` and the bypass flag is absent: read the trail, find the last
  `ticket review` event for this ticket, compare `normalise_actor` of its `by` against the
  accepting actor. Refuse on a match, exit 1.
- Message must name the submitter and the rule, in the voice the rest of the file uses:
  say who submitted it and that a second actor must accept, and point at `--no-review` for
  solo work.
- **No submit event means no conflict.** A ticket already sitting in `review` from before
  this change, or one moved by hand, has nobody to conflict with — proceed. Refusing there
  would strand every in-flight ticket in every repo on the day this ships.
- The whole read-check-write is already inside `feature_lock`; do not take a second lock.

- [x] Same-actor accept is refused with exit 1 and the ticket file is byte-identical after
- [x] A different actor accepts normally and the trail records both actors
- [x] A ticket in `review` with no submit event in the trail still accepts
- [x] The refusal message names the submitter
