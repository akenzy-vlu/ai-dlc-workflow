# T-02-04 — submit runs the verification, records it, and refuses on failure

## Context

The join. `_transition` already refuses `review` while done-when boxes are unticked; this
adds the run after that check and before the status rewrite, so a failing verification
leaves the ticket file untouched exactly as a failing checklist does.

ADR-01 makes execution opt-in per repo. The unconfigured path is the one most repos will
take on day one and it must be indistinguishable from today's behaviour apart from a single
informational line.

## Implementation notes

- Resolve the command: `evidence.command` with `{tests}` replaced by the ticket's `tests:`
  list, space-joined. No `tests:` on the ticket means nothing to run — warn and proceed
  (a ticket with no tests is not a failing ticket).
- Order inside the lock: checklist check → resolve → run → **append the record** → decide.
  Recording before deciding is what puts a failing run on the trail; a run recorded only on
  success would discard the most useful artifact, the same reasoning `ai-dlc-verify` uses
  for screenshotting failures.
- Non-zero exit, failure to start and timeout all refuse with exit 1 and a message that
  points at `aidlc evidence <ticket>` for the tail.
- Absent `evidence:` block: no execution, one line saying verification is not configured
  for this repo, proceed. A config error from T-02-01 refuses instead — a typo must not
  read as "not configured".
