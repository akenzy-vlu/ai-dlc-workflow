# T-02-03 — The evidence record — extend HISTORY_KEYS, append, and aidlc evidence <ticket>

## Context

Per ADR-02 an evidence record is an ordinary trail event with `action: "evidence"`, so it
inherits `merge=union`, the `(ts, id)` sort, the dedupe and `reconcile` for free.

The load-bearing detail: `entry_id` (`aidlc.py:340`) hashes only `HISTORY_KEYS`. Two runs of
the same ticket by the same actor in the same second would hash identically and
`read_history`'s dedupe would **silently drop one**. `HISTORY_KEYS` must therefore gain
`command`, `exit`, `digest` and `duration_ms`. `tail` stays out of the id on purpose — it is
evidence for a human, not identity.

`depends_on` includes `T-01-03` as a write-ordering constraint on `aidlc.py`, not a logical
dependency.

## Implementation notes

- Extend `HISTORY_KEYS`; confirm `stamp_entry` and `read_history` need no other change.
- `fold_gate` must ignore `action: "evidence"` — it is not a gate transition. Verify it
  already does by falling through, rather than adding a branch that could drift.
- `save_state`'s key whitelist stays as it is: the YAML view stays a summary, and the run
  detail lives only in `history.jsonl`.
- `aidlc evidence <ticket>` prints the recorded runs newest first: time, exit, duration,
  command. Print the tail only for a failing run — that is when a human needs it.

## Done when

- [x] Two runs of one ticket in the same second produce two records, neither deduped away
- [x] `aidlc reconcile` on a trail containing evidence records rebuilds the same gate
- [x] `.aidlc-state.yaml` gains no new keys
- [x] `aidlc evidence T-xx-yy` lists runs, showing the tail only for failures
