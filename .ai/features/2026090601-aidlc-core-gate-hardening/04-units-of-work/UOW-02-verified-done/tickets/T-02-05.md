# T-02-05 — Document the evidence block and the ticket tests: field in templates.md

## Context

`templates.md` is named in `CLAUDE.md` as the source of truth for schema, and the scripts
parse these shapes with regexes — a documented shape that does not match the parser is how
a gate starts silently returning "missing". Two things are new: the ticket's `tests:` list
and the repo's `evidence:` block.

`depends_on` includes `T-01-04` because both tickets write `SKILL.md`.

## Implementation notes

- Add `tests:` to the ticket frontmatter example, next to `verifies:`, and say plainly what
  it feeds: the `{tests}` substitution in the repo's command.
- Add the `evidence:` block to the Configuration section, with every key, its default, and
  a one-line reason. Say that its absence is a supported state, not an unfinished setup.
- Extend the "What the controller checks" table with the G4 row's new condition, marked as
  applying from ruleset 5 — the bump itself lands in T-03-03, so word it as the rule, not as
  a claim about what the shipped tool does today.
- Note the bounded-tail behaviour where a reader will meet it: a failing test's output goes
  into a file that is usually committed.
