# T-02-01 — Read the evidence: block through the mini-parser, one nested level

## Context

`find_config` and `load_layers` (`uow_graph.py:206` and `:244`) already walk up to
`.ai/aidlc.yaml` and read flat scalars and lists with regexes. The header of that file is
explicit that this is a fixed-schema subset, not a YAML parser, and it must stay that way.
The `evidence:` block is the first key needing one level of nesting.

The key is `evidence:`, **not** `verify:` — that block belongs to `ai-dlc-verify`, which is
out of scope for this feature and must keep sole ownership of it.

## Implementation notes

- `load_evidence_config(feature_root)` returns a dict or `None` when the block is absent.
  `None` is the signal the whole feature degrades on — it must never raise.
- Keys: `command` (string), `timeout` (int, seconds), `output_ceiling` (int, bytes),
  `aging_hours` (int). Apply defaults for everything but `command`.
- Handle exactly one nested level — a block of `key: value` lines indented under
  `evidence:`. Anything deeper is out of contract; say so in a comment next to the regex.
- A block present but with no `command` is a configuration error worth naming, not a
  silent `None` — that distinction is what keeps a typo from looking like "not configured".
- Reuse `find_config`; do not add a second config walker.

## Done when

- [x] Absent block returns `None`, and nothing raises on a malformed file
- [x] A present block returns command, timeout, ceiling and aging hours, with defaults
- [x] A block with no `command` reports a config error distinct from "not configured"
- [x] `layers:` parsing is unchanged, inline and block forms both still work
- [x] `python3 -m py_compile skills/ai-dlc-core/scripts/uow_graph.py` is clean
