# T-03-02 — check_g4 requires passing evidence at ruleset 5, with a migration hint below it

## Context

`check_g4` (`aidlc.py:696`) today asserts every ticket is `done` and every UoW checklist is
ticked. This adds a third condition, applied only when the plan's stamp is ≥ 5 **and** the
repo opted in with an `evidence:` block. Both conditions matter: a ruleset-5 plan in a repo
that never configured verification has nothing to produce, and failing it would punish a
repo for upgrading.

## Implementation notes

- Branch on the stamp from T-03-01, not on the repo-level pin.
- Ruleset ≥ 5 and configured: every `done` ticket needs at least one evidence record with
  `exit: 0`. Name the tickets that lack one — a gate that says "some ticket" is a gate
  someone has to bisect by hand.
- Ruleset 4, or unstamped: today's logic exactly, plus one hint naming the authored ruleset
  and how to move. A hint, never a failure.
- Keep the ruleset-4 branch a readable path, not a special case buried in a conditional;
  T-03-03's regression exercises it and it will outlive this feature.
- A ticket marked done via `--no-review` still needs a passing run. The bypass skips the
  reviewer, not the verification.

## Done when

- [x] Ruleset-5 plan, configured repo, ticket with no passing run → G4 fails naming it
- [x] Ruleset-5 plan, unconfigured repo → G4 behaves as today
- [x] Unstamped plan → G4 behaves as today, with a migration hint and no failure
- [x] A `--no-review` ticket is still held to the evidence requirement
