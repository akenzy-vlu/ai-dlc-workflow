# T-03-04 — Prove the console is untouched — pnpm test, typecheck, and a py_compile sweep

## Context

`apps/api/src/contexts/planning/infrastructure/filesystem-feature-plan.reader.ts`
deliberately mirrors `REQUIRED_INTENT_SECTIONS` and `assumption_rows` from `aidlc.py`, and
the API shells out to the controller. `CLAUDE.md` is explicit that a `RULESET` bump or a
frontmatter-schema change can break the console's parsers silently. This feature edits
neither of those two mirrored structures, so the expectation is green — this ticket is what
turns that expectation into a checked fact, and it is the last thing in the slice for a
reason.

The state file gains one key (`ruleset`) and `history.jsonl` gains one `action` value. Both
are additive; the point of this ticket is to confirm the readers ignore what they do not
recognise rather than to assume it.

## Implementation notes

- `pnpm skills:check`, then `pnpm typecheck`, then `pnpm test` from the repo root.
- `git diff --stat -- apps/` must be empty. If it is not, something in this feature strayed
  out of scope and the finding belongs in the register before the diff is kept.
- Open a feature in the console against a plan carrying the new `ruleset` key and confirm
  it renders — a passing unit suite does not prove the reader tolerates an unknown key.
- Record the result in `docs/PILOT-RUNBOOK.md` beside the post-install check from T-03-03.

## Done when

- [x] `pnpm skills:check`, `pnpm typecheck` and `pnpm test` all pass from the repo root
- [x] `git diff --stat -- apps/` is empty
- [x] The console renders a plan whose state file carries the new `ruleset` key
- [x] The runbook records both checks
