# T-01-03 — TicketDetailDrawer, and the row click that opens it

## Context
Same container/view/props shape as `AgentRunDrawer`, opened the same way (an id in state,
owned by `UnitsOfWorkPanel`). `TicketActions`, unmodified, supplies AC-06 — it already takes
every prop this drawer has on hand.

## Implementation notes
- `UnitsOfWorkPanel` gains `openTicketId: string | null` state and passes the `Ticket` for
  that id (from the same `ticketsById` map already built) to the view
- `Table`'s `onRow`: `(record) => ({ onClick: () => setOpenTicketId(record.id) })`. The
  existing Agent/Actions column buttons already stop the click from doing anything else —
  antd buttons call `stopPropagation` by default; confirm this holds rather than assuming it
- Drawer body: title (untruncated), status/layer/type/estimate as a small descriptions
  block, `Context` and `Implementation notes` as prose blocks (omit each entirely when
  null), `touches`/`verifies`/`dependsOn`/`blocks`/`assumptions` as plain lists, the full
  done-when checklist (reuse the `[x]`/`[ ]` rendering already written for a UoW's
  definition-of-done in `units-of-work-panel.view.tsx`), then `<TicketActions>` at the
  bottom with `compact={false}`
- A ticket that is `done` has no meaningful action — `TicketActions` already renders
  nothing for a status with no `ALLOWED_FROM` action available; do not special-case it here

## Verification note
Verified live in the browser against a real tracked project
(`utser-application-mobile`, feature `chat-composer-layout`) — the exact ticket table shown
when this request was raised. A JS-dispatched click on the row opened the drawer with the
full title, layer/type/estimate, `Implementation notes` verbatim (including a nested
`>` blockquote), all 12 done-when items as individual lines, and every structured list
(`touches`, `verifies`, `dependsOn`, `blocks`, `assumptions`) in full.

Clicking the row's own `Reject` button opened only the confirmation dialog `TicketActions`
already provides — the drawer did not also open, confirming the `stopPropagation` fix on
the Agent and actions cells. The dialog was cancelled, not confirmed: nothing on that real
project's ticket was changed.
