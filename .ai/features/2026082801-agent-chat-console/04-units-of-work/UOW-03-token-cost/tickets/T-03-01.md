# T-03-01 — AgentTelemetry gains four nullable token counts

## Context
`emptyTelemetry()` is the shape every run starts from, and `mergeTelemetry` is why the
fields can be filled in at any point in the stream without erasing each other — it skips
`undefined` and `null` in the patch on purpose, because the session id arrives on the first
event and the cost on the last.

Four more fields with the same discipline.

## Implementation notes
- `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, all `number | null`
- All null in `emptyTelemetry()` — never 0. Zero is a number a run reported; null is a run
  that reported nothing, and the UI has to tell them apart
- Nothing else changes here. `restoreTelemetry` takes the whole object and keeps working;
  the `JSONB` column and the file driver both store it as-is

## Amendment during construction
`depends_on: [T-02-02]` was added, and it is a real edge rather than bookkeeping: widening
`AgentTelemetry` is what makes `restoreTelemetry`'s bare assign lossy for runs persisted
earlier, and the fix lands in `agent-run.ts` — T-02-02's file. The spec added here proves
that fix from the telemetry side.

A-05 was also confirmed while this ticket was open, against a real
`claude -p --output-format stream-json --verbose` run: the `result` frame carries `usage`
with the four keys T-03-02 assumes. T-03-03 still owns the regression test.
