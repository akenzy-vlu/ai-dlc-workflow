# T-02-01 — AgentDefinition declares a resume invocation

## Context
Resume is a per-agent capability, never inferred (ADR-03). The catalog's own doc comment
explains the cost of guessing: a wrong flag does not error, it opens an interactive session
that hangs forever behind a pipe and holds the ticket's run slot until the timeout kills it.

So the default is "cannot resume", and an agent opts in by declaring the argv.

## Implementation notes
- `AgentDefinitionProps.resumeArgs: string[] | null`, defaulting to `null` in `create`
- `get canResume(): boolean` — `resumeArgs !== null`
- `argsForResume(sessionId: string, prompt: string): string[]` substituting both
  `{{session}}` and `{{prompt}}`; throw `InvalidValueError` when called on a definition
  with no `resumeArgs`, rather than falling back to `argsFor`
- Extend `AgentConfigEntry` so `agents.json` can declare `resumeArgs` for a CLI the built-in
  table does not cover
- `withAvailability` must carry `resumeArgs` through — it rebuilds the whole props object

## Done when
- [x] A definition with no `resumeArgs` reports `canResume: false`
- [x] `argsForResume` substitutes `{{session}}` and leaves other args untouched
- [x] `argsForResume` on a non-resumable definition throws rather than guessing a flag
- [x] `withAvailability` preserves `resumeArgs`
- [x] `pnpm test` is green
