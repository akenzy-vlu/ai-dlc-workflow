# T-02-06 — AgentLauncherService.reply()

## Context
A second entry point beside `launch`, sharing its conflict rules and its hand-off,
differing in what goes in the prompt and what goes in argv.

The one thing it must *not* share is the controller call. `launch` moves a `todo` ticket to
`in_progress`; `reply` requests no transition at all (ADR-05). That is what makes AC-08
true by construction — there is no path from a reply to a gate.

## Implementation notes
- Resolve the parent run; refuse if `telemetry.sessionId` is null, if the definition
  reports `canResume: false`, if the ticket is `done`, or if any run is active on the ticket
- Each refusal is a `ConflictException` whose message is the reason from the error taxonomy
  in `03-logical-design.md`, worded for a person to read
- The active-run check reuses `store.list({ ticketId, active: true })` filtered by
  repository and slug — the same expression `launch` uses, not a second implementation
- Build the child run: same repository, slug, ticket, agent and `cwd` as its parent;
  `parentRunId` set; `promptPreview` is the reply text alone; `actingAs` in the same
  `"<agent> (via <human>)"` shape
- Reuse `execute()` unchanged, passing `resumeSessionId`. That keeps `handOff`, the
  assembler invalidation and the failure handling identical for launches and replies
- Add `thread(repositoryId, slug, ticketId)` returning summaries in `createdAt` order with
  `canReply` and `cannotReplyReason` resolved server-side, so the UI never re-derives the rule
- Do **not** call `this.tickets.transition` anywhere in this method

## Amendment during construction
Drafted with no test file in `touches` — the plan gave the exhaustive refusal matrix and
the gate proof to T-02-08. But this ticket's own done-when items are behavioural claims
("starts with the parent's session id", "no brief appended", "thread orders correctly"),
and inspecting the source is not the same thing as proving it. Added
`apps/api/test/agent-reply.spec.ts`: the happy path, one instance of each of the four
refusals, and `thread()`'s ordering and reason-surfacing. `touches` amended to match.

T-02-08 is unchanged in scope — it still owns the exhaustive matrix (all four refusals in
one table) and the specific proof that a clean reply's hand-off records exactly one
transition, `submit`, via a recording double. Two tests both exercising `reply()` from
different angles is not duplication here: this one is "does it work", that one is "can it
ever move a gate".
