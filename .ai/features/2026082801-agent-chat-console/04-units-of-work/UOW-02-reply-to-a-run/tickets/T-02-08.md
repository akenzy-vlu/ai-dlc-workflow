# T-02-08 — Refusal matrix and the proof that chat cannot move a gate

## Context
AC-08 is the acceptance criterion this whole feature is judged on: chat must be powerless
over plan state. A test that only checks the happy path would let a later refactor
reintroduce a transition without anyone noticing.

Follow the existing suite's constraints — domain tests, no I/O and no subprocesses. The
process port and the ticket operations are both doubles.

## Implementation notes
- Table-drive the four refusals: no session, agent cannot resume, another run active on the
  ticket, ticket already done. Assert the status code and that the process double was never
  called
- The gate proof: a fake `TicketOperations` that records every call. Post a reply, let the
  run finish cleanly, and assert the only transition recorded is the `submit` from
  `handOff` — no `start`, no `accept`
- Assert the file-system double saw no write under any `.ai/` path
- Attribution: a reply's `actingAs` matches the shape a launch produces, and `launchedBy`
  is the human
- Ticket already in `review`: assert the hand-off's `submit` is accepted rather than
  refused, since `ALLOWED_FROM` permits review → review. This is the case the error
  taxonomy calls a no-op, and it is worth pinning because it reads like a bug

## Amendment during construction
"Assert the file-system double saw no write under any `.ai/` path" assumed a filesystem
port this service does not take directly. `TicketOperations.transition` is the only seam
through which a ticket transition — and so any write under the target repo's `.ai/` — can
happen from here; `aidlc.py` is the sole writer of that state, and this port is the only
way to reach it. So the proof is the same recording double the ticket already asks for:
every call it receives across a whole reply is exactly one `submit`, never a `start` or an
`accept`. Written as such rather than adding an FS double that would double-cover the same
fact from a level below.
