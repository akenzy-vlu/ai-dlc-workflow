# T-02-02 — AgentRun carries parentRunId

## Context
The link that makes a thread a thread (ADR-02). One field, plus the two accessors the
thread query and the UI need.

## Implementation notes
- `AgentRunProps.parentRunId: string | null`
- `get parentRunId`, `get isReply` (`parentRunId !== null`)
- `create` keeps requiring `launchedBy`; a reply is attributed to a person exactly as a
  launch is, and `actingAs` keeps the same `"<agent> (via <human>)"` shape
- Do not add a `children` collection. The thread is a query over `list()`, and an aggregate
  that holds its own descendants would have to be kept coherent by hand

## Amendment during construction
Two things were added beyond the drafted scope, both inside this ticket's own file:

1. `apps/api/test/agent-run.spec.ts`, because the ticket was drafted with no spec listed
   and the done-when items are behavioural. `touches` amended rather than the test being
   left out or added unlisted.
2. `restoreTelemetry` now merges over `emptyTelemetry()` instead of assigning. T-03-01
   widens `AgentTelemetry`, and both stores restore with `raw.telemetry ?? emptyTelemetry()`
   — so a run persisted before the new counters existed would have come back with them
   `undefined`, which is neither "not reported" nor a number, and which vanishes from the
   next serialisation. The fix belongs to the aggregate, and the aggregate is this file.
   T-03-01 therefore now declares a dependency on this ticket.
