# T-02-04 — Declare claude's resume invocation, and nobody else's

## Context
Verified on this machine 2026-08-28: `claude --help` documents
`-r, --resume [value]` — "Resume a conversation by session ID". That is the only one of the
four verified, and per ADR-03 the other three ship without chat rather than with a guess.

Ordered after T-01-01 because both edit the same table in the same file.

## Implementation notes
- `claude`: `resumeArgs: ['-r', '{{session}}', '-p', '--output-format', 'stream-json', '--verbose']`
- `codex`, `cursor-agent`, `copilot`: leave `resumeArgs` unset — the default `null` is the
  statement, and a comment should say it is unverified rather than unsupported
- Extend `listAgents()` in the launcher so the client can see `canResume` per agent
- Note the invocation keeps `promptVia: 'stdin'`: the reply arrives the same way a brief
  does

## Amendment during construction
`touches` was drafted with only the catalog, but the done-when item "`GET /api/agents`
includes `canResume`" lands in `listAgents()` — `agent-launcher.service.ts`. Amended rather
than the item being dropped. T-02-06 rewrites the same file and already depends on this
ticket, so the pair stays ordered and no write-conflict hazard appears.
