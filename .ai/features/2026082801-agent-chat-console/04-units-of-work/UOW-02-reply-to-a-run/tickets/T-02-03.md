# T-02-03 — Persist parentRunId in both store drivers

## Context
`AGENT_RUN_STORE` has two drivers and both must round-trip the new field. Runs written
before this feature have no `parentRunId`, and they must keep loading — absent means "not a
reply", never an error.

The entire schema change is one column. Token counts need none at all: `telemetry` is
already `JSONB` (ADR-04).

## Implementation notes
- File driver: `parentRunId?: string | null` on `PersistedRun`; read as
  `?? null` so old files load. Note `save` only writes terminal runs — that is unchanged
- Postgres: **append** a migration step, never edit a shipped one:
  `ALTER TABLE agent_run ADD COLUMN IF NOT EXISTS parent_run_id TEXT`
- The step is inline SQL in `migrations.ts`; `nest build` copies no `.sql` files, so a
  separate file would exist in the repo and be missing from `dist/`
- `pg-agent-run.store.ts` reads with `SELECT *`, so only the `Row` interface, the `INSERT`
  column list and the row mapper need the field
- `agent_run_scope_idx` already covers `(repository_id, slug, ticket_id)` — the thread
  query needs no new index

## Done when
- [x] A reply round-trips through the file driver with its `parentRunId`
- [x] A run file written before this change still loads, reporting `isReply: false`
- [x] The migration runs clean twice in a row on an existing database
- [x] No shipped migration step was edited
- [x] `test/migrations.spec.ts` and `pnpm test` are green
