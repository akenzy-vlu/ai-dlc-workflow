# T-04-04 — Live activity streams into the thread

## Context
The socket already carries `agent.run` frames with the run id and the current activity;
the drawer already consumes them. This routes them into the right thread entry instead of
into one flat pane.

No polling. The push channel exists precisely so the console does not poll.

## Implementation notes
- Route each frame to its entry by run id; a frame for a run not in this thread is dropped
- The "currently doing" line renders from `currentActivity`, which the domain already
  returns as null once the run is terminal — read it, do not cache the last tool seen
- Keep the follow-the-tail scroll behaviour, and keep it releasable: a person who scrolls up
  mid-run is reading, and yanking them back to the bottom is the behaviour they are
  scrolling away from
- A run that finishes while the thread is open updates in place; no refetch

## Amendment during construction
"The `plan-events` folder" undersold what routing activity into a thread actually needs.
`apps/web/src/presentation/features/plan-events/` holds only the dispatch hook
(`use-plan-events.ts`); the socket payload's own type lives in
`apps/web/src/data/datasource/socket/plan-events.datasource.ts`, and neither the server's
`activity` field nor the web side had anywhere to land — no `AgentActivity` type existed on
the client at all, and `AgentRunEvent` dropped `activity` on the floor even though the
gateway already sent it (verified by reading `plan-events.gateway.ts` and
`agent-event.bridge.ts`: the frame always carried it, just discarded on ingestion).

Wired end to end rather than working around it:
- `AgentActivity` entity + `AgentActivityKind` enum (client had neither), mirrored on the
  model and threaded through `toAgentRun`
- `AgentRunEvent.activity` added to the socket datasource, narrowed through
  `toAgentActivityKind` the same way `toAgentRunStatus` narrows status
- `stream.slice.ts` gained `agentActivity: Record<runId, AgentActivity | null>` — a
  redux-patched map, not a refetch, which is what makes "no refresh" and "disappears the
  instant it stops" both true without waiting on the invalidate-driven refetch that already
  existed for exitCode/telemetry
- `ThreadEntry` merges the live map over the fetched snapshot's `currentActivity`
  (`undefined` in the map = trust the snapshot; present, even `null` = trust the socket)
- One small addition outside the touches list entirely: `app.css` gained the `@keyframes`
  the "currently doing" dot's animation references — a `style` prop naming an undefined
  keyframe animates nothing, silently
