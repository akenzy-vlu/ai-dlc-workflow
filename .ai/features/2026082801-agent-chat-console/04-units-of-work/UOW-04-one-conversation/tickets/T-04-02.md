# T-04-02 — The thread component

## Context
Replaces the drawer's single terminal pane with a conversation. Each entry is a run: the
prompt that started it, then what it did. A reply is a run whose prompt is short and whose
parent is the entry above it.

Ordered after T-03-04 because the drawer view is the same file, and the token panel it adds
has to survive this rewrite rather than be lost in it.

## Implementation notes
- Follow the container/view/props split every other feature here uses
- One entry per run, oldest first. Header: agent label, the human it is attributed to,
  status tag, timestamp. Body: the prompt, then the transcript
- A reply's prompt is the message — render it as sent text, not as a code block
- An initial run's prompt is a multi-kilobyte brief: collapse it behind a disclosure,
  expanded never by default
- Keep the transcript's terminal styling for the run output; only the framing changes
- The existing scroll-follow behaviour lives in `agent-run-drawer.tsx`; move it to the
  thread rather than reimplementing it

## Amendment during construction
Three real gaps surfaced while building this, none of them cosmetic:

1. **No repository methods.** T-04-01 wired `getAgentThread`/`replyToRun` at the RTK Query
   layer but never extended `AgentRepository` — the port presentation actually depends on
   in this codebase (no component may call an RTK hook directly). Added `useThread`/
   `useReply` to both `agent.repository.ts` and `agent.repository.impl.ts` here, since this
   is the first ticket that needs them. T-04-01 stays `done`; this is a missing file in its
   `touches`, not a functional regression — nothing it shipped was wrong.
2. **No prompt text ever left the API.** Neither `summarise()` nor `getRun()` returned
   `promptPreview` — it was used only to build the spawned command. But "the initial brief
   is collapsed, a reply's prompt is the message" is this ticket's own done-when, and
   without the text there is nothing to collapse or show. Added `promptPreview` to
   `summarise()`, and `promptPreview`/`parentRunId`/`isReply` to the web model/entity (the
   API already returned the latter two, unread on the client since T-02-06).
3. **The drawer's shape changed, not just its body.** `AgentRunDrawerProps` still takes only
   `runId` — the call site in `agent-runs-page.view.tsx` is untouched. The opened run is now
   fetched only to learn which ticket it belongs to; the container then fetches the thread
   itself and derives Stop's target from whichever run in it is still active, since a reply
   started after the drawer opened is a different run id than the one on the URL. The
   per-run Descriptions block (session badge, token panel, launched-by/started/finished)
   moved into `ThreadEntryView`, one instance per run — each run has its own telemetry, and
   a single header could only ever show one of them.
