# T-04-01 — Thread query and reply mutation on the web data layer

## Context
Follows the shape already in `agent.endpoints.ts`: a `build.query` with a
`transformResponse` through a mapper, and tags for invalidation.

New files rather than additions to `agent.entity.ts` — that file is being edited by T-01-03
and T-03-04 in other slices, and a thread is its own concept anyway.

## Implementation notes
- `getAgentThread` query keyed by `FeatureRef & { ticketId }`, providing
  `[{ type: 'AgentRun', id: ticketId }]`
- `replyToRun` mutation invalidating that tag, so the thread refetches on send
- `AgentThread` entity: the ordered run summaries, `canReply`, `cannotReplyReason`
- Export both through the barrels; the rest of the app imports from `@domain/entities`

## Done when
- [x] The thread query returns runs oldest-first
- [x] A successful reply invalidates the thread and it refetches
- [x] `cannotReplyReason` survives the mapper unchanged — it is shown verbatim
- [x] `pnpm typecheck` is green
