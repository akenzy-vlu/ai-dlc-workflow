# T-01-03 — Surface telemetry and isResumable on the web run model

## Context
`summarise()` in `agent-launcher.service.ts` has been returning `telemetry` and
`isResumable` all along; the web model, entity and mapper never picked them up, so the
client drops both. That is why the drawer can say "running" and nothing about cost or
session.

This ticket adds the whole telemetry object rather than only `sessionId`, because it is one
payload field and splitting it would mean editing the same three files again in UOW-03.

## Implementation notes
- Mirror `AgentTelemetry` from the API: `sessionId`, `model`, `costUsd`, `numTurns`,
  `durationMs`, `toolCalls` — every one nullable except `toolCalls`
- Map `isResumable` through as a boolean
- In the drawer's Descriptions block: show the session id in mono, truncated, and a
  "Resume available" tag when `isResumable` is true
- A run that reports no session shows neither — no placeholder, no "unknown" tag. The rail
  stays quiet rather than displaying a field with nothing in it

## Done when
- [x] `telemetry` and `isResumable` reach the drawer through the mapper
- [x] A finished run with a session shows the session id and the badge
- [x] A finished run with no session shows neither
- [x] `pnpm typecheck` is green
